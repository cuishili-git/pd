# ESP32-P4 采集 NE555 波形 · 今天就能做

> 目标只有一个：**电脑上看到 12V 方波**。看到波形 = NE555 模块正常起振 = Step 1 通过。
> 适用：微雪 ESP32-P4-WIFI6-DEV-KIT（你手上这块）+ 你的 NE555 集成模块。
> 今天不碰任何高压。

---

## 0. 先记住两句话

1. **12V 绝对不能直接进 GPIO** —— 必须经分压降到 3V 左右。
2. **必须共地** —— NE555 的 GND 和 P4 的 GND 连在一起，否则读数乱跳或全是 0。

---

## 1. 接线（3 根线 + 2 个电阻）

### 物料
| 元件 | 值 | 你手头 |
|---|---|---|
| 电阻 R1 | 10 kΩ | 有 |
| 电阻 R2 | 3.3 kΩ | 没有就用 4.7 kΩ（降到 3.8V，仍在安全内）或 2×6.8k 并联 |
| 杜邦线 | 4 根 | 有 |

### 接法

```
NE555 OUT ────[ 10 kΩ ]────┬──── GPIO23 (ADC1_CH7)
                           │
                         [ 3.3 kΩ ]
                           │
                          GND

NE555 GND ─────────────────┴──── P4 板 GND
```

- **GPIO23 在 40pin 排针左列第 4 脚**（从板子边缘数，认丝印 `GPIO23`）
- GND 任选板上标 `GND` 的黑脚
- 分压节点 = 12V × 3.3 / 13.3 = **2.98V**，安全
- 若用 4.7k：12 × 4.7/14.7 = 3.84V —— **超过 3.3V 了，不行**。必须 ≤3.3k。
  没有 3.3k 就用 **3.3k 或 2.2k**（2.2k → 2.16V，也安全），或者 10k 高边换成 15k（15k+4.7k → 2.86V）。

> **推荐组合（挑一个）**
> - R1=10k, R2=3.3k → 2.98V ✅ 最佳
> - R1=10k, R2=2.2k → 2.16V ✅ 安全，幅度小一点
> - R1=15k, R2=4.7k → 2.86V ✅ 手头有 4.7k 时用这个

### 接完先用万用表验一次（30 秒）

万用表 DCV 20V 档，红表笔接**分压节点**（GPIO23 那点），黑表笔接 GND：

| 读数 | 判断 |
|---|---|
| 1.5~3.2V 之间某值 | ✅ 安全，可以上电 |
| > 3.3V | ❌ 停！电阻接反或阻值不对 |
| 0V | 检查 NE555 是否供电、OUT 是否有输出 |

## 2. 电脑端准备（一次即可）

### 2.1 装 Python 库

打开 CMD（Win+R 输入 `cmd`）：

```cmd
python -m pip install pyserial matplotlib
```

看到 `Successfully installed` 即可。

### 2.2 找到串口号

把 P4 板通过 **Type-C UART 口**（标 `UART` 的那个，CH343P 芯片）插电脑，然后：

```cmd
python D:\workbuddy\docs\pd\tools\serial_plot_ne555.py --list
```

会列出类似：

```
可用串口：
  COM5    USB-SERIAL CH340 (COM5)
```

记下 `COM5` 这个号。**板子上有两个 Type-C 口，一定插 UART 那个**；另一个是 USB OTG，没配 CDC 不会出数据。

## 3. 编译 + 烧录固件

### 3.1 打开 ESP-IDF 终端

从开始菜单找 **"ESP-IDF 5.5 PowerShell"** 或 **"ESP-IDF Command Prompt"**，双击打开。
（不要用普通 CMD，普通 CMD 没有 `idf.py` 命令。）

如果开始菜单里找不到，用这个方式：

```cmd
C:\esp\v5.5.2\esp-idf\export.bat
```

### 3.2 进目录、编译、烧录、开监控

在 ESP-IDF 终端里逐行输入：

```cmd
cd /d D:\esp32\p4\esp32-p4-platform-main\examples\esp-idf\20_adc_ne555_capture
idf.py set-target esp32p4
idf.py build
```

编译通过后，插上板子，烧录：

```cmd
idf.py -p COM5 flash monitor
```

> `COM5` 换成你在 2.2 步查到的号。
> 看到 `NE555 ADC capture (ESP32-P4)` 和 `Format: timestamp_us,raw_adc` 就说明固件跑起来了。
> 先按 `Ctrl+]` 退出 monitor（否则串口被占用，Python 打不开）。

**如果 `idf.py build` 报错**，把报错内容发我。代码是按 ESP-IDF 5.5 官方 API 写的，理论上能过。

## 4. 电脑上看波形

再开一个普通 CMD：

```cmd
python D:\workbuddy\docs\pd\tools\serial_plot_ne555.py COM5
```

会弹出一个实时波形窗口，控制台每 0.5 秒打印一行测量结果。

### 看到什么算成功

```
100.2 Hz  周期 9.98 ms  占空比 50.1%  hi=2773(2.98V) lo=0(0.00V)
```

| 现象 | 判断 |
|---|---|
| 波形是方波，读数 ~100Hz 或 ~50Hz | ✅ **成功，Step 1 通过**，可以进高压区了 |
| `未起振/无跳变 hi=xx lo=xx` 且 hi≈lo | ❌ NE555 没起振，查模块供电和频率电位器 |
| 波形是直线但 hi≈2773 | OUT 恒高，模块没振荡 |
| 波形是直线但 hi≈0 | 接线断开 / 没共地 / 插错 Type-C 口 |
| 读数 50Hz 或 100Hz 之外的奇怪值 | 模块频率电位器没调好，转一下 |

### 想存数据

```cmd
python D:\workbuddy\docs\pd\tools\serial_plot_ne555.py COM5 --save D:\workbuddy\docs\pd\ne555_capture.csv
```

## 5. 三个最容易踩的坑

| 坑 | 症状 | 原因 |
|---|---|---|
| **12V 直连 GPIO** | 板子可能烧 | 一定要分压，这是硬性红线 |
| **没共地** | 波形乱跳或全是 0 | NE555 GND 必须与 P4 GND 相连 |
| **monitor 没退出** | Python 报"端口被占用" | 在 ESP-IDF 终端按 `Ctrl+]` |
| **插错 Type-C 口** | `--list` 找不到串口 | 插标 `UART` 的那个口，不是 USB OTG |
| **虚拟环境缺失** | `idf.py` 报 no module named click | 用 ESP-IDF 专属终端，不要用普通 CMD |
