# 07 · 串口采集与示波器上位机开发实录

> 2026-11-18 · 用 ESP32-P4 采集 NE555 方波，PyQt6 自研示波器，当天从零到全链路跑通。
> 本文是**代码 + 每个坑的根因分析**，不是操作教程（操作见 [06](06-ESP32P4采集NE555波形_今天就能做.md)）。

---

## 1. 系统架构

```
NE555 模块(12V) ──OUT──[10kΩ]──┬──[3.3kΩ]──GND     ← 分压：12V→2.98V，保 GPIO
                               └── GPIO23 (ADC1_CH7)
ESP32-P4 ── 2000Hz 采样 ── CSV 行 ── UART 921600 ── CH343 ── 电脑
电脑 ── PyQt6+pyqtgraph 示波器：触发 / 测量 / 游标 / CSV 保存
```

**带宽账本**（为什么必须 921600）：2000 行/s × 每行约 13 字节 ≈ 24 kB/s，
115200 串口只扛得住 ~11.5 kB/s，会丢数据；921600 ≈ 92 kB/s，余量近 4 倍。

## 2. 下位机固件（ESP-IDF 5.5.2，`main/test_ne555.c` 全文）

```c
#include <stdio.h>
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"
#include "esp_adc/adc_oneshot.h"
#include "esp_timer.h"
#include "esp_rom_sys.h"
#include "driver/uart.h"

#define SAMPLE_PERIOD_US  500      /* 2000 Hz */
#define ADC_UNIT_ID       ADC_UNIT_1
#define ADC_CHANNEL       ADC_CHANNEL_7   /* GPIO23 */
#define CONSOLE_BAUD      921600   /* 硬编码：运行时强制改波特率 */

void app_main(void)
{
    /* 0. 控制台 UART 波特率强改 921600（详见坑①） */
    ESP_ERROR_CHECK(uart_set_baudrate(CONFIG_ESP_CONSOLE_UART_NUM, CONSOLE_BAUD));

    /* 1. 打开 ADC1，禁用 ULP */
    adc_oneshot_unit_handle_t unit;
    const adc_oneshot_unit_init_cfg_t init_cfg = {
        .unit_id  = ADC_UNIT_ID,
        .ulp_mode = ADC_ULP_MODE_DISABLE,
    };
    ESP_ERROR_CHECK(adc_oneshot_new_unit(&init_cfg, &unit));

    /* 2. 通道：12 位 + 12dB 衰减（约 0~3.3V） */
    const adc_oneshot_chan_cfg_t chan_cfg = {
        .atten    = ADC_ATTEN_DB_12,
        .bitwidth = ADC_BITWIDTH_12,
    };
    ESP_ERROR_CHECK(adc_oneshot_config_channel(unit, ADC_CHANNEL, &chan_cfg));

    printf("Format: timestamp_us,raw_adc | GPIO23 / ADC1_CH7 | 2000 Hz | baud 921600\n");

    /* 3. 采集循环：时间节拍保证严格 2000Hz */
    while (1) {
        int64_t now  = esp_timer_get_time();
        int raw      = 0;
        ESP_ERROR_CHECK(adc_oneshot_read(unit, ADC_CHANNEL, &raw));
        printf("%lld,%d\n", now, raw);

        int64_t remain = (now + SAMPLE_PERIOD_US) - esp_timer_get_time();
        if (remain > 0) {
            esp_rom_delay_us((uint32_t)remain);
        }
    }
}
```

**三个设计决策的理由**：

| 决策 | 理由 |
|---|---|
| `adc_oneshot` 循环，不用 `adc_continuous`(DMA) | 只要"看到波形"，15 行代码 vs 一整套回调+解析；2000Hz 单次读取绰绰有余。以后做 MHz 级局放再换 DMA |
| `esp_rom_delay_us` 忙等对齐节拍 | 不用 vTaskDelay（ms 粒度太粗），保证采样间隔严格 500µs，时间戳真实可信 |
| 波特率代码里硬改硬件 | **sdkconfig 是生成物**，`set-target` 会重新生成并冲掉手工修改；`uart_set_baudrate` 直接写硬件寄存器，不依赖驱动安装，谁也冲不掉 |

**`main/CMakeLists.txt`（有陷阱，见坑⑤）**：

```cmake
idf_component_register(SRCS "test_ne555.c"
                    INCLUDE_DIRS "."
                    PRIV_REQUIRES esp_driver_uart esp_adc esp_timer)
```

**`sdkconfig.defaults`**（双保险）：

```

CONFIG_ESP_CONSOLE_UART_BAUDRATE=921600
```

## 3. 上位机关键代码（PyQt6 + pyqtgraph，单文件 `scope_app.py`）

### 3.1 串口线程：SerialWorker（QThread）

```python
class SerialWorker(QThread):
    sample = pyqtSignal(float, int)      # t_us, raw
    status = pyqtSignal(str)
    error  = pyqtSignal(str)             # 打开失败 → 界面复位

    def run(self):
        import serial
        try:
            ser = serial.Serial(self.port, self.baud, timeout=0.1)
        except Exception as e:
            self.error.emit(f'打开 {self.port} 失败: {e}')
            return
        n_rx = n_ok = n_bytes = 0        # 原始行 / 解析成功 / 字节
        shown = 0
        last_stat = time.time()
        while not self._stop:
            raw = ser.readline()
            if raw:
                n_bytes += len(raw); n_rx += 1
                if shown < 3:            # 控制台打印前3行原始数据，定位乱码
                    print(f'[scope] 串口原始第 {shown+1} 行: {raw[:64]!r}', flush=True)
                    shown += 1
            line = raw.decode('ascii', errors='ignore').strip()
            if ',' in line:
                parts = line.split(',')
                try:
                    t_us, raw_adc = float(parts[0]), int(parts[1])
                except ValueError:
                    continue
                n_ok += 1
                self.sample.emit(t_us / 1e6, max(0, min(RAW_MAX, raw_adc)))
            if time.time() - last_stat >= 1.0:   # 每秒刷新接收统计
                self.status.emit(f'接收统计: {n_bytes} 字节 / {n_rx} 行原始, 解析成功 {n_ok}')
                last_stat = time.time()
        ser.close()
```

**设计要点**：

- **收数在 QThread，绘图在主线程**——串口阻塞绝不卡 UI，中间靠 `pyqtSignal` 跨线程投递（Qt 自动排队，线程安全）。
- **接收统计是排障神器**：`字节>0 且解析=0` → 波特率错（乱码）；`字节=0` → 固件没跑；`解析在涨` → 链路通。三行日志把"没数据"这种模糊故障切成三种确定状态。
- **失败走 `error` 信号**：打开串口失败时主线程复位按钮/标签并亮出错误文本，不让界面说谎（曾出现过"标签显示已连接实际打开失败"的误导）。

### 3.2 边沿测量：线性插值过阈检测

```python
def edge_crossings(t, v, level, rising=True):
    """返回信号穿越 level 的精确时间点（线性插值）。"""
    t, v = np.asarray(t), np.asarray(v)
    s = v - level
    idx = np.where((s[:-1] < 0) & (s[1:] >= 0))[0] if rising else \
          np.where((s[:-1] >= 0) & (s[1:] < 0))[0]
    if len(idx) == 0:
        return np.array([])
    frac = -s[idx] / (s[idx + 1] - s[idx])       # 线性插值出亚采样周期精度
    return t[idx] + frac * (t[idx + 1] - t[idx])
```

- 用**上升沿间隔的中位数**求周期——单个异常沿不会污染读数。
- 占空比 = 每个上升沿到下一个下降沿的中位时长 ÷ 周期。
- 电平用 90/10 百分位而不是 max/min——抗毛刺。

### 3.3 边沿触发提取（波形稳定不漂的核心）

```python
def _extract_window(self, t, v, window, trig_on, level):
    """返回 [(t_rel, v), ...]，t_rel 相对触发点。window=全屏跨度(秒)。"""
    pre, post = window * 0.1, window * 0.9
    if trig_on:
        lv = vmin + (vmax - vmin) * (self.sld_trig.value() / 100.0)
        if vmax - vmin > 0.05:
            cross = edge_crossings(t, v, lv, rising=True)
            # 最后一个能放下完整窗口的触发点
            good = cross[(cross - pre >= t[0]) & (cross + post <= t_end)]
            if len(good):
                t0 = float(good[-1])
                sel = (t >= t0 - pre) & (t <= t0 + post)
                return list(zip(t[sel] - t0, v[sel])), True, t0
    t0 = t_end - post            # 触发丢失 → 退化为滚动窗口
    ...
```

每次刷新都重新搜"最后一个满足窗口约束的上升沿"→ 波形始终以触发沿为 x=0 对齐 → 静止不漂。找不到边沿自动退化为滚动模式。

## 4. 踩坑全记录（当天实战，7 个坑）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| ① | 反复改波特率不生效 | `sdkconfig` 是**生成物**，`set-target` 重新生成冲掉手工修改；`sdkconfig.defaults` 优先级又低于目标默认 | **代码里 `uart_set_baudrate()` 硬改硬件**，绕过整个配置体系 |
| ② | 打开 COM3 没有权限 | Windows 串口**独占**：自己前一个实例 / idf.py monitor 还开着 | 找到旧窗口关掉；monitor 用 `Ctrl+]` 退出 |
| ③ | `connect_serial` AttributeError | `__init__` 引用了不存在的方法（按钮走的 `on_connect` 没被复用） | 命令行 `--port` 也走 `on_connect()` 统一路径 |
| ④ | `esp_timer.h: No such file` | `main` 组件一旦显式写 `PRIV_REQUIRES`，就**失去自动依赖全部组件**的特权 | `esp_driver_uart esp_adc esp_timer` 三个都显式列上 |
| ⑤ | 波形只有一条竖线 | Y 轴锁死 `(-0.25, 3.65)`，而换算满量程 4.4V → 高电平 4.17V **被裁在屏幕外** | Y 轴扩到 `(-0.3, 4.8)`，两处口径必须一致 |
| ⑥ | 一屏只有一个周期 | 时基值被当成"全屏宽度"，示波器惯例是**每格**宽度（×10 格） | `window = 档位值 × 10`；缓冲扩到 22s |
| ⑦ | 轴标 18ms 实际是 18 秒 | 数据单位是秒，轴标签却写 `units='ms'`，pyqtgraph 按标签口径显示 | `units='s'`（pyqtgraph 会按视窗自动切 ms 前缀） |

另外两个通用陷阱：

- **`np.min(arr, initial=np.nan)` NaN 传播**：数组非空也返回 nan，占空比永远算不出来 → 显式判空。
- **pyqtgraph 0.14 移除了 `enableMenu`**：升级后旧 API 直接 AttributeError，删掉即可（右键导出菜单反而有用）。

## 5. 当天实测结论

| 项 | 数值 | 意义 |
|---|---|---|
| 采样率 | 1973~1997 /s | 目标 2000Hz，printf 开销占用 ~1.3%，达标 |
| NE555 高电平 | raw ≈ 3877（显示 4.17V，实际引脚 ≈3.0V） | **模块 OUT 直出 12V（无内置 7805）**——高压区验源判据按此定 |
| NE555 低电平 | raw ≈ 2（0.001V） | 分压链干净 |
| 当前模块频率 | ~1.8Hz（电位器在最低频端） | 待拧到 100Hz/50Hz |

**遗留**：① 电位器拧到 100Hz/50Hz 后复测记录；② 该模块频率范围下限太低，如果拧到头仍达不到 100Hz，需并电容改定时网络。
